/speckit-constitution Establish the constitution for a small Python project. Principles: (1) Standard library only - no third-party runtime dependencies; (2) Fail loudly - invalid input produces a clear message and a non-zero exit status or an error response, never a silent wrong answer; (3) Every requirement is testable - each functional requirement maps to at least one automated pytest test; (4) Simplicity - the smallest design that meets the specification; (5) Secure by default - every specification and plan states the security requirements of each feature, following the OWASP Top 10 and the OWASP Application Security Verification Standard, and each one is tested like any other requirement. At minimum: treat every input (arguments, files, archives, network requests and stored data) as untrusted and validate it; never build SQL, shell commands, file paths or markup from untrusted input by string concatenation - use parameterised queries, encode output for the context it is written into, and resolve file paths inside an allowed directory without following links out of it; store passwords only as salted, deliberately slow hashes, and never keep passwords, tokens or other secrets in plaintext; generate identifiers and tokens with a cryptographically secure random generator and compare secrets in constant time; limit the size of every input and the time and memory any input can consume; check access on every operation, including under concurrent requests; create files with the narrowest permissions that work; and never expose personal data or secrets in output, logs or error messages.
