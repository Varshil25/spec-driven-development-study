# Reading list

The sources read for Part I, and those found later that the study builds on.
Links only: the papers are other authors' work and are not copied here.

## Read in Week 1

| Source | Why it matters here |
| --- | --- |
| Pearce, Ahmad, Tan, Dolan-Gavitt, Karri (2022). [Asleep at the Keyboard? Assessing the Security of GitHub Copilot's Code Contributions](https://arxiv.org/abs/2108.09293). IEEE S&P. | About 40% of Copilot's programs in security-relevant scenarios were vulnerable: the premise for measuring security as an implicit expectation. |
| Perry, Srivastava, Kumar, Boneh (2023). [Do Users Write More Insecure Code with AI Assistants?](https://arxiv.org/abs/2211.03622) ACM CCS. | Users with an assistant wrote less secure code and trusted it more. |
| Rosa, Moreno-Lumbreras, Robles, Gonzalez-Barahona (2026). [Understanding Specification-Driven Code Generation with LLMs: An Empirical Study Design](https://arxiv.org/abs/2601.03878). SANER registered report. | The methodological template: matched tasks, instrumented logging, a registered design. |
| Marri (2026). [Constitutional Spec-Driven Development](https://arxiv.org/abs/2602.02584). | Security constraints in the constitution; one case study reporting 73% fewer security defects. The `sdd_secure` approach tests this idea. |
| Alenezi (2026). [Specification-Driven Development as the Foundation of AI-Native Enterprise Software Engineering](https://arxiv.org/abs/2607.16680). | A governance reference model for SDD, mapped to ISO/IEC 25010. |
| Panda (2026). [Citation Discipline in Spec-Driven Development](https://arxiv.org/abs/2606.30689). | A pre-registered comparison of traceability in three SDD frameworks, including Spec Kit. |
| GitHub (2025). [Spec-driven development with AI: Get started with a new open source toolkit](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/). | Spec Kit's own description of the workflow. |
| GitHub. [spec-kit](https://github.com/github/spec-kit) (version 1.0.6 is used throughout). | The tool under study. |

## Found later (Weeks 5–7)

| Source | Why it matters here |
| --- | --- |
| Claudino et al. (2026). [The EPIC Framework for Spec-Driven Development](https://arxiv.org/abs/2610.07534). | 40 practices for writing specifications, from 114 SDD repositories. |
| Grynets, Kaskun, Salyk, Zhuravchak, Lyashkevych (2026). [Specification-Driven Development Benchmark: Security Knowledge Transition](https://arxiv.org/abs/2606.00167). | Security-enriched specifications reduced hidden-test failures for an agent. |
| Dhuri (2026). [Specification Before Generation](https://arxiv.org/abs/2609.23270). | A pre-registered five-model study: a specification preamble cut security findings from 148 to 23. |
| Feng, Chen, Meyer, Mussbacher (2026). [LLM-Assisted Repository-Level Generation with Structured Spec-Driven Engineering](https://arxiv.org/abs/2605.02455). | Structured inputs help, with effects that vary by system and model. |
| Baltes et al. (2025). [Guidelines for Empirical Studies in Software Engineering involving Large Language Models](https://arxiv.org/abs/2508.15503). | The reporting guidelines this study follows. |
