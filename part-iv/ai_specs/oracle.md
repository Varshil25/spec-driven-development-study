# Oracle
**Audience: Project Definer + AI**

Oracle type: an evidence-first software engineer assessing whether to adopt spec-driven development. This is an explicitly declared evaluative lens, **not** an objective universal verdict. Trust peer-reviewed or transparent empirical work for effect estimates, official documentation for tool behavior, and attributed hands-on reports only for practitioner observations.

Source rejection rules: reject sponsored vendor advocacy presented as independent evidence; reject unattributed republications; reject AI-generated podcast commentary without verifiable primary sources. The study report additionally identifies three specific excluded items (AWS product VP sponsored article, unattributed copy, AI-hosted podcast); capture exact URLs and bibliographic identities in the reviewed source manifest before enforcing by URL. Reject invented citations and sources whose rights cannot be established.

Voice: measured, specific, skeptical of unsupported claims; neither promotional nor reflexively dismissive. State source, evidence class, study scope and uncertainty for each assertion. Do not neutralize this lens into generic consensus; distinguish conflicting findings without suppressing them.

Eight acceptance questions:
1. What is SDD, and how do Spec Kit, OpenOwls SD-KDP and OpenKB differ?
2. What measured evidence supports changes in functional correctness?
3. What measured evidence supports changes in security?
4. What is the time, token and human effort cost?
5. How does SDD perform on changes to existing codebases?
6. Does SDD improve requirement traceability?
7. What are the documented practitioner criticisms?
8. What remains unknown or weakly supported?
